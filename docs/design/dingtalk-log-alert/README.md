# 日志告警卡片设计

本目录保存已确认的日志告警卡片流程、钉钉设计器备份和审核依据。交互设计已覆盖首次告警、持续聚合、AI 修复、多仓库 MR、人工处理、人工关闭及关闭后复发；当前没有生产业务实现。

先阅读[告警卡片方案确认](告警卡片方案确认.md)，其中汇总已确认的卡片职责、状态变化、零未完成时隐藏吊顶、H5 通知规则与验证范围。身份权限、数据库和 AI 执行方案见[平台整体设计](../platform/README.md)：首次钉钉登录自动成为普通用户，可用账号在本人当前所在群内操作，后台提供全平台查询。详细卡片规则见[日志告警卡片设计说明](日志告警卡片设计说明.md)及[吊顶与告警处理工作台设计](吊顶与告警处理工作台设计.md)。需要逐项对照钉钉预览时，阅读自动生成的[卡片流程对照](卡片流程对照.md)。

## 吊顶、群卡片与 H5 交互原型

打开 [alert-workbench.prototype.html](alert-workbench.prototype.html)，底部可切换“群聊 + H5”“H5 完整页”和“手机半浮层”。三种视图共享模拟状态，日志与指标沿用群卡片的标题、颜色、证据区、处理记录和操作；H5 不改成表格列表。

按 2026-10-05 的补充要求，H5 已逐项对照官方模板：移除自行添加的指标走势图、独立状态徽标及装饰图标；指标沿用数值/阈值/时间信息块，日志沿用累计信息、完整 Trace ID、处理进展和人工备注的顺序。群内预览与 H5 共用相同卡片内容，字号、间距和按钮尽量与钉钉 8.0 设计器一致。

单文件仅依赖浏览器，直接打开或在本目录运行：

```bash
python3 -m http.server 8847 --bind 127.0.0.1
```

访问 <http://127.0.0.1:8847/alert-workbench.prototype.html>。`?variant=workspace` 打开完整 H5，`?variant=mobile` 打开手机预览；也可用左右方向键切换。上方“重置预览”恢复初始 6 项告警。

建议依次体验：从吊顶打开列表，给日志追加两条备注，再填写结果并标记已处理；切换指标列表，添加备注，再用页面上方的演示控件模拟监控恢复。页面底部显示 H5 新增群消息数量。浏览、取消和空白提交不增加消息；成功追加备注或完成日志，每次增加一条。任意旧群卡片均展示最新状态，终态隐藏备注入口。

此原型不连接钉钉、不发送消息，刷新即重置。电脑侧栏与手机半浮层是布局模拟，不代表真实客户端、身份验证、业务存储、网络失败、并发或消息投递已经接通。已在浏览器验证主要状态变化、统计、历史记录和 390 px 手机布局。

## 钉钉设计稿

- 名称：AI AlertOps · 日志告警状态卡（设计稿）
- 模板 ID：`03a9f40b-e81b-4efc-a12d-6a59a55a9a32.schema`
- [打开官方设计器](https://editor.dingtalk.com/editor?templateId=03a9f40b-e81b-4efc-a12d-6a59a55a9a32.schema&scene=open_platform&bizId=1791101120958&customBuilder=false&corpId=ding6d039ea9a87c3a7235c2f4657eb6378f&appId=5036643162)
- 模板未发布。已向当前用户的“钉钉卡片助手”投放模拟测试卡，未发送到业务群。

打开后选择“预览模式”。底部下拉框包含 18 个模拟场景；编辑模式会同时显示条件隐藏的节点，不能用它判断实际按钮显隐。

预览可操作场景切换、复制 ID、备注展开和取消，以及本地模拟追加备注、标记已处理。首条备注成功后标题与颜色同步变为处理中，完成后变为已处理并隐藏编辑入口。备注支持连续追加、最近三条倒序展示。演示身份与时间是模拟值，真实保存、失败和多用户并发尚未接入；处理记录与 MR 入口仍展示说明。

## 文件与复现

| 文件 | 用途 |
| --- | --- |
| `告警卡片方案确认.md` | 当前确认方案的统一入口，区分已定规则、后续设计与接入待验收，记录原平台参考依据 |
| `日志告警卡片设计说明.md` | 已确认的业务规则、流程图、接入约束和验收条件 |
| `吊顶与告警处理工作台设计.md` | 日志/指标统计、H5 列表与操作、有效变更通知和多卡片一致性 |
| `alert-workbench.prototype.html` | 吊顶、群卡片及 H5 的单文件交互原型；三种视图、内存数据、无真实发送 |
| `card-flow.json` | 状态、18 个场景、备注及聚合规则的源数据 |
| `build_design.py` | 使用 Python 标准库生成设计器导入包和场景说明 |
| `log-alert-card-design.json` | 官方设计器导入备份，不能直接当作生产发送参数 |
| `design-preview-data.json` | 模拟变量、场景和模板标识 |
| `卡片流程对照.md` | 与场景源数据同步生成的预览对照说明 |
| `verify_design.py` | 核对设计文件、状态约束和生成结果一致性 |
| `verify_preview.mjs` | 使用 Node 标准库执行生成表达式和按钮更新，校验本地预览流转 |
| `preview-verification.json` | 实际浏览器验证范围和未验证边界 |
| 三个 `reference.json` 文件 | 生成器使用的官方组件样例备份 |

在项目根目录执行：

```bash
python3 docs/design/dingtalk-log-alert/build_design.py
python3 docs/design/dingtalk-log-alert/verify_design.py
```

只修改源数据和生成器，再重新生成；不要单独修改生成的 JSON 或场景说明。组件结构参考[钉钉官方卡片样例](https://github.com/open-dingtalk/dingtalk-card-examples)，本地保留原始引用以便复现，不需要生成时下载依赖。

**这是一份设计器模拟模板。** `preview_mode="no"` 仅隐藏演示入口，并不会把所有场景表达式自动转换成真实业务绑定。正式接入必须替换模拟内容、时间、身份、MR URL 和 `view_*` 表达式，并重新验证实际钉钉客户端。

## 本次调整

统一待处理／处理中／已处理，首条备注成功即表示有人跟进。移除独立上线观察场景，默认仅保留添加备注、标记已处理；结束时填写一句处理结果。已处理后禁止追加备注，历史只读。AI 与 MR 不会重开已完成卡片。

标题、颜色和按钮由同一主状态派生，避免预览场景与本地操作状态不一致。实际验证范围见 `preview-verification.json`。

日志卡使用待处理／处理中／已处理。指标卡使用待处理／处理中／已恢复：告警触发时待处理，首条备注保存成功后处理中，匹配的监控恢复事件到达后已恢复；已恢复禁止追加备注。指标规则已同步到[独立模板与说明](../../../design/metric-alert-card/README.md)，并在官方设计器验证三状态和连续备注。置顶编号打开详情的核查见[消息详情跳转核查](消息详情跳转核查.md)。

最新入口方案已调整为吊顶分别统计日志与指标告警，点击按钮在钉钉右侧打开当前群 H5 未完成列表。[新版吊顶模板](../../../design/alert-ceiling-card/README.md)已在官方设计器保存，未发布；日志和指标的待处理、处理中合计大于 0 时展示，全部完成或恢复后隐藏，再有未完成告警时重新展示。仅有处理中事项时也展示。原型已验证这一显隐流程；正式接入需在归零时调用关闭互动卡片吊顶接口，撤下整块区域。

H5 成功提交且产生卡片可见的业务变更后，向来源群发送一张最新卡片；多条卡片对应同一轮次，统计只计一次。原先“同轮始终只发送一张卡片”的约束被该人工操作通知规则替代；监控重复事件、AI/MR 更新仍按既定流程更新已有卡片。新布局和联动可在上述本地原型体验；生产 H5、真实消息联动及群吊顶自动展示／关闭尚未接入。官方设计器的 18 场景预览仍仅验证日志卡内部交互。

后续提出的“未完成时钉住、完成后取消钉住，以及打开全部钉住消息”方案，见[钉住消息能力核查](钉住消息能力核查.md)。用户限定只接受企业应用或机器人直接调用的公开服务端 API，不接入 CLI／MCP。当前未查到符合条件的钉住／取消钉住接口，因此此方案不纳入当前设计；原生钉住列表跳转也未确认。
