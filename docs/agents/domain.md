# 领域文档

本仓库采用单上下文（single-context）布局。

## 阅读规则

探索仓库前，读取根目录 `CONTEXT.md`，
并阅读 `docs/adr/` 中与当前工作有关的架构决策记录。

若未来出现根目录 `CONTEXT-MAP.md`，先读取该索引，
再阅读其中与当前任务有关的上下文文档及上下文内 ADR。

文档或目录不存在时，直接继续工作，不报告缺失，
也不预先建议补建。由 `domain-modeling` 技能在领域术语
或架构决策明确后按需创建。

## 文件布局

- `CONTEXT.md`：领域概念、术语及关系。
- `docs/adr/`：架构决策记录，文件名采用递增编号和主题，
  如 `0001-<主题>.md`。

## 术语一致性

在事项标题、方案、诊断假设、代码和测试名称中使用领域概念时，
遵循 `CONTEXT.md` 中的术语，避免使用术语表明确排除的同义词。

所需概念尚未收录时，先判断是否引入了项目并不使用的说法；
确认属于领域模型的实际缺口后，记录下来供 `domain-modeling` 处理。

## ADR 冲突

方案或实现与现有 ADR 冲突时，明确指出冲突的 ADR 编号、
冲突内容及重新讨论的原因，由用户决定是否调整原决策。
