# NOTICE 业务提示卡设计说明

2026-10-04 用户确认本版设计。本文记录业务提示卡的展示内容、视觉参数、模板变量及验收范围，供后续接入和维护使用。

业务通知使用 `NOTICE` 类型。卡片用于展示 Notice 级别日志中的 Message，并提示所属项目和运行服务。客户根据通知自行处理，卡片不承担处理流程，也不记录处理结果。

## 展示内容

卡片从上到下分为三个区域：

| 区域 | 内容 | 展示规则 |
| --- | --- | --- |
| 标题栏 | 小标题 `NOTICE`，大标题「业务提示」 | 固定文案，白字配橄榄绿背景 |
| 来源行 | `${project}  /  ${service}` | 项目与运行服务合并为一行，使用辅助文字色；较长时允许换行 |
| 内容区 | `${message}` | 在浅灰圆角区域中直接展示该条日志的 Message |

当前预览示例：

```text
NOTICE
业务提示

智享云 / brace-iot

租赁宝欠费，请及时通知商户
```

「业务提示」是固定标题，Message 是正文。模板不根据 Message 推导其他状态，也不将原文重新概括成业务结论。例如，Message 提到欠费或 OTA 时，仍然使用相同的标题、布局和橄榄绿色。

## 视觉规格

版式参考用户提供的「AI AlertOps · 日志告警状态卡（设计稿）」截图：彩色标题栏、两级白色标题、单行来源信息，以及浅灰圆角内容区。用户明确选择保留业务提示卡原有的橄榄绿，不采用参考截图的橙棕色。

以下数值为设计器配置，单位为 px；设备字号使用钉钉语义样式，实际渲染随客户端适配。

| 元素 | 当前配置 |
| --- | --- |
| 整体 | 白色正文，圆角 12；外层左右和顶部内边距为 0，底部内边距为 6 |
| 标题栏背景 | 浅色模式 `#6F7C35`；深色模式 `#56622B` |
| 标题栏容器 | 四边内边距 16；左上、右上圆角 12；底部两角为 0 |
| `NOTICE` | 白色，加粗脚注文字；PC 和移动端均为 12；外边距为 0 |
| 「业务提示」 | 白色，加粗一级标题；PC 24、移动端 20；上边距 6，其余外边距为 0 |
| 来源行 | `common_level2_base_color`；描述文字样式，PC 12、移动端 14；左右及上边距 16，下边距 0；最多 2 行 |
| 内容区容器 | 背景使用 `common_bg_color`；圆角 8；四边内边距 12；左右外边距 16，上边距 12，下边距 10 |
| Message | `common_level1_base_color`；正文样式，PC 14、移动端 17；外边距为 0，最多 100 行 |

标题栏直接贴合卡片顶部，来源行与内容区左侧对齐。正文背景及文字使用平台语义色，随浅色和深色主题适配；橄榄绿只表达提示类型，不表示已恢复、成功或已处理。

## 模板变量

草稿只有三个普通文本变量，没有状态变量或本地交互变量。

| 变量 | 含义 | 示例 |
| --- | --- | --- |
| `project` | 通知所属项目的展示名称 | `智享云` |
| `service` | 产生日志的运行服务名称 | `brace-iot` |
| `message` | Notice 日志的 Message 原文 | `租赁宝欠费，请及时通知商户` |

当前 Mock 数据如下。这里只是模板变量示例，不是钉钉发送 API 的完整请求体。

```json
{
  "project": "智享云",
  "service": "brace-iot",
  "message": "租赁宝欠费，请及时通知商户"
}
```

接入方根据来源日志的 Notice 级别选择本模板，并把该条记录的项目、服务和 Message 映射到以上变量。模板顶部的 `NOTICE` 是固定文字，不是客户端过滤日志的条件。

Message 使用基础文本组件直接展示，不依赖 Markdown 格式或状态解析。正式数据不能用上述 Mock 值补齐；数据来源、有效性校验和消息发送沿用接入项目的约定。

## 通知边界

- 卡片没有按钮、输入框、处理备注、已读或已处理标记，不需要卡片操作回调。
- 不设置进行中、成功、失败、欠费中等卡片状态，不随消息内容切换红色或绿色。
- 不展示告警次数、持续时间、处理进度、负责人或关闭记录，也不触发 AI 排查流程。
- 客户在卡片外自行处理业务，不要求返回卡片确认；卡片无需据此更新处理状态。

NOTICE 不参与未完成告警统计和 H5 未完成列表，与[告警卡片方案确认](../../docs/design/dingtalk-log-alert/告警卡片方案确认.md)保持一致。[日志告警卡](../../docs/design/dingtalk-log-alert/日志告警卡片设计说明.md)和[指标告警卡](../metric-alert-card/README.md)各自的处理、备注或恢复规则不适用于本卡片。

本设计只规定提示内容和展示方式，不新增业务状态机、处理记录或关闭逻辑。通知的发送频率、去重及失败重试由接入方现有通知机制负责，本次没有另行设计或实现。

接入阶段验收以下内容：

1. Notice 日志正确使用本模板，项目和服务对应当前记录，Message 与来源原文一致。
2. Message 内容变化时，仍显示固定的 `NOTICE` 和「业务提示」，保持橄榄绿色，不出现处理状态或操作入口。
3. 校验长项目名、长服务名、多行及长 Message 在实际客户端中的换行和可见范围，尤其是当前来源行 2 行、正文 100 行的展示上限。
4. 在桌面端和移动端检查浅色、深色主题的文字对比度、圆角及留白。
5. 确认 NOTICE 不进入未结束告警统计，不触发日志告警或指标告警的处理、备注、恢复与关闭流程。
