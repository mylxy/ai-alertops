## 自动显示与隐藏

**显示条件：日志待处理 + 日志处理中 + 指标待处理 + 指标处理中 > 0。**

| 当前群状态或变化 | 吊顶行为 |
| --- | --- |
| 没有未完成事项 | 默认不创建、不展示吊顶，也不留零数量卡片或空白占位 |
| 新增首个待处理事项 | 开启吊顶，显示两组统计与 H5 入口 |
| 待处理变为处理中 | 保留吊顶，只改变状态分布，未完成总数不变 |
| 只有处理中事项，待处理为 0 | 继续展示吊顶 |
| 一类全部完成，另一类仍未完成 | 保留吊顶，完成的类别计数为 0 |
| 日志标记已处理或指标有效恢复 | 减少对应类别和状态计数 |
| 最后一个未完成事项结束 | 关闭本应用对应的吊顶，移除整块群顶部区域 |
| 之后又出现新的待处理事项 | 重新开启吊顶，展示最新统计 |

只按本群告警事项/轮次去重计数。重复事件、累计次数、多张同轮消息卡不增加未完成数。指标添加首条备注变为处理中，但必须等待监控有效恢复才移出统计；日志人工标记已处理后移出。两种终态均禁止追加备注。

吊顶隐藏不关闭用户已经打开的 H5，也不删除群内历史告警消息。已打开的 H5 可以继续展示本次完成结果或“当前没有未完成告警”。仅查看、切换分类、开启或隐藏吊顶不额外发送一张告警通知。

## 钉钉显隐接入约定

模板中的条件可见只用于让设计器按零项场景隐藏内容，**不能代替关闭群吊顶**。后端须依据最新群统计调用公开接口管理实际容器：

- 从 0 变为非 0：使用[创建并开启互动卡片吊顶](https://open.dingtalk.com/document/development/send-group-helper-message)，`POST /v2.0/im/topBoxes`。
- 保持非 0：更新已开启吊顶的统计数据，避免每次备注都新建一个吊顶。
- 从非 0 变为 0：使用[关闭互动卡片吊顶](https://open.dingtalk.com/document/development/close-interactive-card-ceiling)，`POST /v2.0/im/topBoxes/close`，关闭本应用持有的 `outTrackId`，不影响其他应用的吊顶。

保存群与吊顶实例的关联；重新开启遵循平台实例规则。按群串行协调显隐和更新，执行前检查最新数量，避免较旧的关闭请求盖过新告警的开启请求。失败后按最新状态重试，不能宣称接口请求发出就已经隐藏。

群需满足场景群或已安装本应用群聊酷应用等官方接入条件。当前测试群只验证了普通群入口卡和 H5 跳转，尚未作为真实吊顶开启/关闭的验收证据。

## H5 链接

`workbench_url` 绑定一个钉钉多端容器链接。桌面端使用 `pc_slide=true`，移动端使用 `im_open_hybrid_panel`，通过 `open_platform_link` 分流。参考官方[链接跳转规范](https://open.dingtalk.com/document/development/link-jump-specification)。

当前模拟地址是 `http://127.0.0.1:8847/alert-workbench.prototype.html?variant=workspace&embed=1`，仅运行预览服务的 Mac 可访问。`embed=1` 去掉模拟群聊、额外顶部导航和视图切换栏，关闭页面使用钉钉自身侧栏控件。正式接入时替换为可访问的 H5 地址，按钉钉身份校验当前用户、来源群与权限，不能仅凭 URL 中的群 ID 授权。

## 模板字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `log_pending` | 非负整数 | 本群待处理日志轮次数 |
| `log_processing` | 非负整数 | 本群处理中日志轮次数 |
| `metric_pending` | 非负整数 | 本群待处理指标轮次数 |
| `metric_processing` | 非负整数 | 本群处理中指标轮次数 |
| `workbench_url` | 字符串 | 校验后的钉钉容器入口链接 |

`log_count`、`metric_count`、`total_count`、`has_unfinished` 由以上四个计数计算，不另传可能不一致的合计或显隐开关。统计按同一份业务快照计算。服务端拒绝负数、不完整计数、越权群及无效链接。

## 设计文件与场景

统一运行 `python3 design/alert-ceiling-card/build_preview.py`。生成器仅使用 Python 标准库，不调用钉钉或业务服务。

| 文件 | 场景 |
| --- | --- |
| [mixed.json](mixed.json) | 默认：日志 4、指标 2，总数 6 |
| [processing-only.json](processing-only.json) | 待处理均为 0，处理中共 3 项，继续展示 |
| [metric-only.json](metric-only.json) | 日志为 0，指标未完成 2 项，继续展示 |
| [empty.json](empty.json) | 所有计数为 0，预览模式隐藏全部内容 |
| [overflow.json](overflow.json) | 三位数量示例，总数 175，不生成编号列表 |
| [h5-entry-onebox.json](h5-entry-onebox.json) | 默认吊顶模板，与 mixed 内容相同 |
| [h5-entry-test-card.json](h5-entry-test-card.json) | 同款普通群测试卡，用于侧栏入口验证 |

这些文件是设计器导入封装，不能直接作为发送 API 请求体。导入后待对话框关闭，再切换“预览模式”检验条件可见；编辑模式会展示隐藏内容。验收结束恢复 mixed 并保存。

已验证默认和仅处理中场景正常显示，零项场景在设计器预览中不显示内容。生成器检查统计及多层 URL 编码。Mac 群内同协议文字链接右侧打开 H5 已目视确认；手机实机、群卡内部按钮自动点击、真实群吊顶自动开启与关闭、业务同步仍需后续接入验收。完整工作流见[吊顶与告警处理工作台设计](../../docs/design/dingtalk-log-alert/吊顶与告警处理工作台设计.md)。
