## 三种展示

| 条件 | 展示 | 标题栏背景 |
| --- | --- | --- |
| 指标仍告警，没有备注 | 告警中 | 红色 |
| 指标仍告警，已有备注 | 已备注 · 等待恢复 | 琥珀橙 |
| 收到监控恢复事件 | 已恢复 | 绿色 |

只有“告警中、已恢复”属于监控状态。“已备注”由备注内容派生，不新增人工处理状态，也不改变监控状态。恢复可以直接从无备注的告警进入，不要求先写备注。

卡片保留指标名称、值、阈值、对象与主要维度、首次和最近接收/恢复时间、持续时间、备注内容及备注作者。业务操作只有添加一次备注。没有认领、负责人、标记处理中、静默、人工关闭或关闭确认页。

备注输入框默认隐藏，只显示「添加备注」。点击后展示输入框和「提交备注」，隐藏添加入口。提交成功后显示备注内容、作者和时间，同时隐藏输入框及所有备注按钮，不再允许填写或修改。尚未提交时仅展开或输入文字不改变卡片状态。

提交备注不会降低指标值，也不会结束告警。收到恢复事件后保留只读备注；没有备注时允许在恢复后首次添加，添加后仍保持已恢复状态。

## 与日志卡统一的视觉规格

样式依据为日志卡的[设计生成器](/Users/seven/work/worktrees/ai-alertops/log-alert-card-design/docs/design/dingtalk-log-alert/build_design.py)和已保存模板 03a9f40b-e81b-4efc-a12d-6a59a55a9a32.schema：彩色标题栏配白字，正文使用白色背景，内容分组使用浅灰信息块。此次只读取参考设计，没有修改日志卡。

正文与辅助文字使用平台语义色，跟随浅色/深色模式。未恢复时指标值持续使用红色，避免备注后的过渡色被理解为指标已经正常。

## 如何体验

1. 打开模板并选择「预览模式」。编辑模式会显示条件隐藏的内容。
2. 初始为红色标题栏。备注框隐藏，只显示「添加备注」。
3. 点击「添加备注」展开输入框和「提交备注」，填写例如“已修正采集规则，等待监控恢复”。空内容时不能提交。
4. 输入值同步后点击「提交备注」：显示备注及模拟作者、时间，标题栏变为琥珀橙，指标值仍为 92.6%。输入框、添加按钮和提交按钮全部消失。
5. 点击底部「模拟监控恢复」，标题栏变绿，指标变为模拟恢复值 43.2%，原备注继续只读展示。
6. 刷新页面并选择「预览模式」，可回到无备注的红色初始状态。

底部的恢复按钮属于设计演示控件，不是业务操作，正式接入时移除。预览中的身份、时间、指标值与阈值均为模拟数据；输入的备注仅保存在当前预览内，重新加载或切换设备/主题可能重置模拟数据。

## 后端接入边界

本次仅调整钉钉独立草稿，没有接入备注持久化或真实告警流，没有发布模板，没有向群发送测试消息。

- 备注只写入本轮的备注内容、作者和时间，并返回卡片最新状态。服务端需原子保证每轮只能成功写入一次，拒绝重复提交和覆盖；仅隐藏按钮不能代替该约束。不能沿用带有人工关闭含义的操作来实现备注；保存失败时保留填写入口，不应展示为已备注。
- 由 Alertmanager 等监控来源的 resolved 事件更新恢复状态、恢复时间和观测值。仅修改规则、暂停采集或没有新告警，不能由卡片自行推断已经恢复，应以接入方提供的明确恢复信号为准。
- 同一轮 firing 更新指标及最近接收时间，同时保留备注；恢复后的下一次 firing 新建一轮，备注不自动继承。
- 更新原卡仍是设计目标，需持久化每轮告警与目标群的卡片标识，再由后端更新对应卡片。
- 原有“实例 ID＋指标键”的聚合方式继续作为现状依据，维度是否纳入聚合键仍需确认。最近接收时间不能冒充真实采样时间。
- 恢复后仍无备注时允许首次添加；已有备注时不再开放填写或修改，不触发告警状态变化。正式接入需校验有效非空内容和实际回调用户身份。
